Portfolio Build Instructions

You are helping build a polished engineering portfolio website for Phil Boctor, a recent Yale Mechanical Engineering graduate targeting mechanical design, product design, robotics hardware, aerospace hardware, and product development roles.

The goal is not to build a flashy generic portfolio. The goal is to build a clean engineering design journal that shows how Phil thinks through real hardware problems.

Core principles:

Process beats final result.
Tradeoffs beat buzzwords.
Specific engineering decisions beat vague claims.
Clean and simple beats flashy.
Do not invent metrics, results, dates, or project details.
Use TODO markers where information or images are missing.
Avoid em dashes.
Avoid generic phrases like “passionate about innovation.”
Make the tone polished, grounded, and conversational.
Make Phil sound like an early-career product design engineer, not a student trying to sound impressive.

Technical requirements:

Use Next.js App Router.
Use TypeScript.
Use Tailwind CSS.
Keep the site static deployable on Vercel.
Use minimal dependencies.
No CMS.
No database.
No contact form.
No dark mode.
No unnecessary animation library.
Use responsive layouts.
Use semantic HTML and accessible alt text.
Keep content easy to edit through structured TypeScript data or Markdown/MDX.

Design direction:

White or off-white background.
Charcoal text.
Subtle blue or neutral accent.
Lots of whitespace.
Clean typography.
Large visual areas.
Simple project cards.
Case-study style project pages.
More Apple product case study than flashy startup site.

Whenever you build or edit:

Read PORTFOLIO_BRIEF.md first.
Preserve the site vision.
Do not overbuild.
Ask for missing content only when needed.
After coding, run the build if possible and fix errors.
Give a concise summary of what changed and what still needs input.
